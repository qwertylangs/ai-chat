# Удаление чата

**Дата**: 2026-09-06
**Статус**: принят

## Контекст

Чат можно создать, но не удалить — список в сайдбаре только растёт.

## Решение

### Бэкенд

`DELETE /api/chats/{chat_id}` → `204 No Content`.

- `get_own_chat` даёт `404` на чужой или несуществующий чат.
- `Chat.messages` получает `cascade="all, delete-orphan"`, поэтому `db.delete(chat)`
  сносит и сообщения. Не завязываемся на `PRAGMA foreign_keys` SQLite —
  каскад на уровне ORM работает одинаково и на Postgres.

### Фронтенд

- `api.deleteChat(id)`; `request()` возвращает `undefined` на `204`, не парся тело.
- Одна кнопка-корзина в шапке чата (`.chat-title`, рядом с названием активного
  чата), `aria-label="Удалить чат"`, заблокирована во время стрима. В списке чатов
  кнопок нет — удаляется всегда текущий открытый чат.
- `deleteActiveChat()`: `window.confirm('Удалить чат?')` → запрос → убрать чат из
  `chats` → `activeChatId = chats.value[0]?.id ?? null` (при `null` очищаем
  `messages` — возврат к пустому состоянию) → `search.value = ''`. Ошибка → баннер,
  список не трогаем.
- Активируется первый чат общего списка (`chats[0]`). Поиск сбрасывается (как в
  `createNewChat`), чтобы новый активный чат был виден в сайдбаре, даже если он не
  проходил фильтр.

## Критерии приёмки

1. Кнопка удаления одна, в шапке активного чата; в списке чатов её нет.
2. Клик → `confirm`; отмена ничего не делает.
3. Подтверждение удаляет чат с сервера вместе со всеми его сообщениями.
4. После удаления активируется верхний чат списка, грузятся его сообщения, поиск сбрасывается.
5. Удаление последнего чата возвращает к пустому состоянию (шапки с корзиной нет).
6. Нельзя удалить чужой чат (`404`), удаление несуществующего — `404`, без токена — `401`.
7. Каскад сносит только сообщения удаляемого чата, соседние не трогает.

## Тестирование

- pytest `api/tests/test_chat_delete.py`: своё удаление (204 с пустым телом, чат и
  его сообщения исчезли, соседний чат цел), чужой чат `404`, несуществующий `404`,
  без токена `401`.
- e2e `e2e/tests/delete.spec.ts`: корзина одна и в шапке; удаление активного чата;
  сброс активного поиска при удалении; отмена в диалоге; удаление последнего чата.
  `confirm` управляется через `page.on('dialog', …)`.
- `api.test.ts`: `deleteChat` шлёт `DELETE` и не падает на пустом теле `204`.

### Инфраструктура

e2e переведены на `workers: 1`: бэкенд ходит в общий SQLite-файл, и параллельные
спеки начали ловить `database is locked`. Сюита из ~14 тестов последовательно
идёт ~10 c.

## Вне scope

Переименование чата, отмена удаления (undo), массовое удаление, мягкое удаление
(корзина/восстановление), подтверждение чем-то кроме нативного `confirm`.
