# Поиск по чатам — расширение на содержимое

**Дата**: 2026-09-06
**Статус**: принят
**Развивает**: `2026-09-06-chat-search-design.md` (там поиск был только по названию и
только на клиенте; раздел «Вне scope» этого документа больше не актуален).

## Контекст

Клиентский фильтр по `title` не находит чат по тому, что в нём обсуждалось.
Пользователь помнит содержание переписки, а не название (которое к тому же
автогенерируется из первого сообщения).

## Решение

Отдельная ручка **`GET /api/chats/search?q=<запрос>`** → `list[ChatOut]`.

- Авторизация обязательна; возвращаются только чаты текущего пользователя.
- Порядок — как в `GET /api/chats`: свежие сверху.
- `q` обязателен (`min_length=1`); пустой или из одних пробелов → `422`.
- Матчинг: запрос и «стог сена» чата (название + тексты всех сообщений)
  приводятся функцией `_fold` — нижний регистр и `ё → е`. Запрос бьётся на слова
  по пробелам; чат подходит, если **каждое** слово входит в стог как подстрока.
- Реализация: чаты пользователя грузятся с сообщениями (`selectinload`) и
  фильтруются в Python. Потолок — тысячи чатов на пользователя; дальше SQL LIKE
  или FTS5. Помечено `lazy:`-комментарием в коде. Фолдинг `ё/е` намеренно в
  Python, а не через SQL `ILIKE`: при переезде на Postgres поведение не поедет.

Фронт: `api.searchChats(q)`; в `ChatView.vue` непустой запрос с дебаунсом 250 мс
идёт в ручку, пустой — показывает полный список из памяти. Клиентский фильтр по
`title` удалён.

## Критерии приёмки

1. Чат находится по слову из названия.
2. Чат находится по слову из текста сообщения, которого нет в названии.
3. Несколько слов — AND: каждое слово должно встретиться (в любом сообщении или
   названии), иначе чат не в выдаче.
4. `ё` и `е` взаимозаменяемы в обе стороны и в запросе, и в содержимом.
5. Регистр не важен.
6. Чужие чаты не находятся.
7. Пустой/пробельный `q` → `422`; отсутствие совпадений → `[]`.
8. Выдача отсортирована свежими сверху.
9. В сайдбаре непустой запрос ищет через ручку; очистка возвращает полный список;
   «Ничего не найдено» показывается, когда поиск завершён и результатов нет.

## Вне scope

Подсветка совпадений, ранжирование по релевантности, морфология и опечатки,
пагинация выдачи. Знаки препинания — часть слова: запрос `борща!` не найдёт
`борща` (слово бьётся только по пробелам).
