# E2E-тесты идут через стаб OpenRouter, а не через мок в браузере

Ответ ассистента приходит стримом от внешнего провайдера, поэтому e2e нужен
детерминированный источник SSE. Вместо перехвата запроса в браузере поднимаем
локальный стаб OpenRouter (`e2e/fake_openrouter.py`, stdlib `http.server`) и
переключаем на него бэкенд настройкой `OPENROUTER_BASE_URL`: так под тестом
остаётся весь реальный путь — SSE-генератор `stream_assistant_reply`, прокидывание
чанков наружу и сохранение ответа в БД после завершения стрима.

**Considered Options**:
- **Мок через `page.route`** — отклонён: перехват `POST /api/chats/{id}/messages`
  в браузере подменяет собственный ответ приложения, и весь бэкендовый путь стрима
  вместе с сохранением сообщения остаётся непроверенным.
- **Реальный ключ OpenRouter** — отклонён: тесты становятся платными, медленными
  и недетерминированными (текст ответа каждый раз разный).

**Consequences**:
- `base_url` клиента перестал быть константой и читается из настроек
  (`openrouter_base_url`); по умолчанию это по-прежнему реальный OpenRouter.
- Формат чанков стаба должен оставаться OpenAI-совместимым (см. ADR-0001) — иначе
  `openai` SDK не разберёт стрим.
- Тесты стартуют три процесса (стаб, uvicorn с отдельной SQLite, vite dev) —
  это делает `playwright.config.ts` через `webServer`.
